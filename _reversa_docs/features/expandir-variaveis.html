Visão Geral

Substitui as referências $NOME e $? dentro dos tokens pelos valores da tabela de ambiente, depois de a gramática ser validada e antes da remoção de aspas. O resultado alimenta clean_tokens (unit analisar-linha-de-comando) e, a partir dele, os argumentos dos comandos 🟢.

Responsabilidades

  • Selecionar os tokens que podem ser expandidos (categoria VAR e que não começam com ') 🟢
  • Extrair o nome da variável de cada $ 🟢
  • Buscar o valor na tabela hash, inclusive a chave especial ? 🟢
  • Reescrever o token no lugar (tks[i]), repetindo até não restar $ 🟢
  • Garantir a ordem expandir → remover aspas 🟢

Regras de Negócio

Seleção do token

  • RX-01: só são expandidos tokens com lexema exatamente VAR (contêm $ e têm mais de 1 caractere) 🟢
  • RN-20: um token que começa com ' não é expandido: '$HOME' → $HOME 🟢 (observado)
  • RN-20 (parcial): aspas simples que não estão no início do token não protegem: a'$HOME' → a/home/u 🟢 (observado). ⚠️ O bash dá a$HOME
  • Aspas simples dentro de aspas duplas são literais e o conteúdo é expandido: "'$HOME'" → '/home/u' 🟢 (observado), igual ao bash
  • $ sozinho é WORD e fica literal: echo $ → $ 🟢 (observado)
  • Alvos de redirecionamento e delimitadores de heredoc nunca chegam aqui, porque a gramática rejeita VAR depois de operador (BUG-13): cat << $EOF → Syntax ERROR! 🟢 (observado)

Nome da variável

  • RN-24: o nome começa logo depois do $ e vai até o primeiro caractere do conjunto " ' , : . / [ ] { } = - + * ! @ # ou espaço, ou até o fim do token 🟢
  • $ não é delimitador: em $HOME$USER o nome é HOME$USER, que não existe, e o token vira vazio (BUG-05) 🟢 (observado). ⚠️ O bash concatena os dois valores
  • _, letras, dígitos e ? fazem parte do nome: $X_Y procura X_Y; $?abc procura ?abc e o token vira vazio 🟢 (observado). ⚠️ No bash, $?abc → <status>abc
  • ${NOME} não é suportado: { é delimitador, o nome fica vazio e o token vira vazio 🟢 (observado). ⚠️ O bash suporta
  • Parâmetros posicionais e especiais ($1, $$, $!) não existem; viram vazio ou seguem as regras acima 🟢 (observado para $1)

Substituição

  • RN-21: $NOME existente → o trecho $NOME é trocado pelo valor e o prefixo e o sufixo do token são preservados: pre$HOME/pos → pre/home/u/pos 🟢 (observado)
  • Vários $ separados por delimitadores no mesmo token são expandidos um por um, da esquerda para a direita: "$HOME $USER" → /home/u luis; $HOME.$USER → /home/u.luis 🟢 (observado)
  • RN-22: $? → valor da chave ? da tabela, gravada por exec_list ao fim de cada execução ("?"=0 no início da sessão) 🟢
  • RN-23 / RX-02: variável inexistente → o token inteiro vira "", com prefixo, sufixo e outras variáveis: abc$NOPE → ""; "a $NOPE b" → "" (BUG-05) 🟢 (observado). ⚠️ O bash remove só o $NOPE
  • Variável existente com valor vazio (Z=) → o trecho vira "" e o resto é preservado 🟢 (observado)
  • O token vazio continua na lista de argumentos como ""; o echo ignora argumentos vazios, mas um comando externo os recebe: ls $NOPE → ls: cannot access '': No such file or directory, $?=2 🟢 (observado na revisão de 2026-11-22). ⚠️ O bash descarta a palavra
  • RX-06: se o valor contém $, ele é expandido de novo: D='x$USER' → xluis 🟢 (observado). ⚠️ O bash não reexpande valores
  • RX-06 (falha): um valor que se refere a si mesmo (A='$A', B='-$B') causa loop infinito; o shell trava 🟢 (observado: processo morto pelo timeout depois de 3 s)
  • RN-25 / RX-07: não há divisão de palavras: V='a b' → echo $V passa um argumento a b 🟢 (observado). ⚠️ O bash passaria dois

Interação com as aspas

  • RN-26: a remoção de aspas roda depois da expansão, então as aspas vindas do valor também são removidas: Q='"q"' → echo $Q → q 🟢 (observado). ⚠️ O bash imprime "q"
  • "$X"q → um token, helloq 🟢 (observado), igual ao bash
  • $X"q" e $X'q' → dois tokens, hello e q (BUG-17, corte na tokenização) 🟢 (observado). ⚠️ O bash dá helloq
  • RN-27: o heredoc não expande variáveis (detalhado em ler-heredoc) 🟢
  • ✅ L-07 (decidida em 2026-11-22, [Revisão]): documentar o comportamento atual. As ⚠️ DIVERGÊNCIAS desta unit são o comportamento especificado, não defeitos a corrigir. (Pendência original: não está decidido se as ⚠️ DIVERGÊNCIAS acima devem ser preservadas ou corrigidas)

Entrada: line->tks (texto cru, com aspas), line->lex (categorias calculadas antes da expansão) e a tabela de ambiente 🟢. Saída: line->tks com as referências substituídas. As aspas continuam no texto e são removidas depois por clean_tokens 🟢.

Fluxo Principal

  1. exec_pipe_line chama expand_var(line, *table) logo depois de a gramática ser aceita (src/facade.c:36) 🟢
  2. Para cada índice i até lex[i] == NULL (src/exec/expand_var.c:24-30) 🟢:
    • se ft_strcmp_len(lex[i], "VAR") e tks[i][0] != '\'':
      • enquanto tks[i] contém $: change_value(line, table, i)
  3. change_value (src/exec/expand_var.c:33-55) 🟢:
    1. key = return_var_key(tks[i])
    2. value = search_item(table, key)
    3. value != NULL → tks[i] = join_str_value(key, value, tks[i]); libera o antigo e value
    4. value == NULL → tks[i] = "" (token inteiro descartado); como "" não tem $, o laço do passo 2 termina
    5. libera key
  4. Depois de todos os tokens, exec_pipe_line chama clean_tokens (src/facade.c:37) 🟢

Algoritmo return_var_key

i = 0
enquanto str[i]:
  se str[i] == '$':
     inicio = i + 1
     len = 0
     enquanto str[i] e str[i] não está em "\"',:./[]{}=-+*!@# ":   # o '$' entra na contagem
        len++; i++
     len--                                                        # descarta o '$'
     pare
  i++
retorna substr(str, inicio, len)

Consequência: um segundo $ não interrompe o nome (HOME$USER) 🟢.

Algoritmo join_str_value

se strlen(key) + 1 == strlen(str):      # o token é exatamente "$KEY"
   retorna strdup(value)
i = 0
prefixo = take_prefix_var(str, &i)      # str[0..i), i fica no '$'
novo = prefixo ? prefixo + value : strdup(value)
i += strlen(key) + 1                    # pula "$KEY"
se str[i]: novo = novo + sufix_var(str, &i)
retorna novo

O atalho do início compara só tamanhos. Ele é correto porque o corte de tokens garante que um token com prefixo é sempre mais longo que $KEY 🟡.

A expansão só lê a chave; ela é tratada como qualquer outra variável 🟢.

Fluxos Alternativos

  • **Token que começa com ':** ignorado inteiro, mesmo que tenha "$X" depois: 'a'"$HOME" → a$HOME 🟢 (observado). ⚠️ O bash dá a/home/u
  • Variável inexistente: token inteiro vira "" (RX-02) 🟢 (observado)
  • Valor vazio: join_str_value produz prefixo + sufixo; o token pode ficar "" 🟢 (observado)
  • **Valor com $:** o while do passo 2 volta a expandir o resultado. Se o valor sempre recria um $, o laço não termina (RX-06) 🟢 (observado)
  • Nome vazio ("$", ${X}, $/): key = "", search_item não acha nada e o token vira "" 🟢 (observado)
  • **$ sozinho:** lexema WORD, nunca chega a change_value 🟢

Dependências

  • hash_table: search_item (leitura), mantida pela unit gerenciar-variaveis-de-ambiente
  • analisar-linha-de-comando: fornece tks e lex; consome o resultado em clean_tokens
  • executar-comando-simples / executar-pipeline: exec_list produz o valor de ?
  • Libft: ft_strchr, ft_substr, ft_strjoin, ft_strdup, ft_strlen

Estado Interno

Sem estado próprio. Lê a tabela (sessão) e reescreve line->tks (linha). Cada iteração de change_value aloca um novo tks[i] e libera o anterior 🟢.

Observabilidade

Nenhuma mensagem nem log. Um nome inválido ou inexistente produz um token vazio em silêncio 🟢.

Riscos e Lacunas

  • 🟢 Loop infinito com valor auto-referente (A='$A', B='-$B'). Um valor assim só entra pela herança do ambiente, porque o próprio export expande o $ antes de gravar
  • 🟢 $ não delimita o nome, então $A$B falha
  • 🟢 $?abc procura a chave ?abc; no bash, $? tem sempre um caractere
  • 🟢 Tokens vazios chegam como argumento "" aos comandos externos (ls $NOPE → ls: cannot access '') (observado na revisão de 2026-11-22); se o vazio é o primeiro argumento, a linha é ignorada (BUG-20)
  • 🟡 Nenhum malloc (ft_substr, ft_strjoin, ft_strdup) tem o retorno testado
  • ✅ L-07 (decidida em 2026-11-22): documentar o as-is. Nota para uma eventual reimplementação corretiva, fora do escopo atual: preservar ou corrigir BUG-05, RX-06, a reexpansão de valores e a remoção das aspas vindas dos valores
  • ✅ L-01 (respondida em 2026-11-22): o alvo é o mínimo exigido pelo subject da 42; word splitting, ${}, $$ e a proteção por aspas simples em qualquer posição ficam fora do escopo 🟢
